# 故事稿写法（通用方法包 short-film v1）

故事稿由四个可写字段组成，工作台按字段保存和比较：

| 字段 | 内容 | 程序检查 |
|---|---|---|
| synopsis 故事梗概 | 按观众看到的顺序写清目标、阻碍、选择、对手回应、结果和回收；把时间自然写进叙述；动机和转折必须写在梗概里。 | 不能为空，不能保留占位 |
| cast 本集角色表 | Markdown 表格，表头至少含「角色ID｜身份与作用｜独立身份基准」；角色ID为小写英文、数字或连字符，不重复；独立身份基准只写「需要」或「不需要」。 | 结构校验 |
| handoff 交接说明 | 目标时长、用户保留项、实际制作风险、尚需验证事项；没有特殊限制时明确写「无」。 | 不能为空 |
| notes 开发辅助（可选） | 故事脊、因果表、时间线或规则／道具说明，按需。 | 无 |

## 梗概

- 完整弧线：开端（想要什么、异常在哪）→ 发展（办法、回应、局面变化）→ 转折与高潮 → 结局（回收与最后笑点）。
- 用因果连接（因为、于是、没想到、结果）。写人物看到了什么、为什么改变做法。
- 聚焦人物行动与因果，不写镜头、景别、逐段秒数或生成提示词。

## 来源与承接

- 来源是想法时，第一稿须能追溯到输入原句。
- 来源是导入的故事稿或剧本时，保留原文中用户明确的前提和人物，按本方法重写成故事稿，不把导入稿当作已审稿。
- 承接前集时，把前集遗留事实写进梗概或交接说明；改为独立成集时不读取遗留。

## 修改

局部修改只改要求涉及的字段；未涉及的字段原样返回或不返回。不得修改输入清单之外的对象。
