# MILO/LEO 精剪

告诉用户正在使用本技能。接收新粗剪或外部调整时先读[交接与实际版本](references/intake-handoff.md)，用户最新明确要求决定创作取舍，当前视频决定可用素材和源时间。脚本都在本目录的 `finecut/` 里，使用细节见同目录 `README.md`。

有采用剧本时，逐段核对人物、对白、关键动作、因果和先后顺序。交接摘要、视觉审片建议和配乐节拍都服从采用剧本。实际录音没有逐句定位时，保留有对白分段的连续原速原声。原片缺音或缺表演应标明素材问题。

## 输入与交付
- **输入**：
  - 粗剪：`自媒体 2/粗剪稿/<MMDD>/<名字>.mp4`，有时附带 `BGM.MP3`
  - 分段粗剪：`粗剪稿/<MMDD>/<名字>/01·xxx_V1.mp4 …`，没有整条 mp4 时先用 `assemble.py` 拼成一条（同序号多版本按用户选择用 `--files` 写明）
  - **画幅**：竖屏 9:16（1080×1920）或横屏 16:9（1920×1080），跟随实际粗剪，不另设参数；交接或用户要求的画幅要和素材一致，不一致先确认
  - 制作交接：本集`正式交付/03_精剪交接.md`，缺失时从剧本/制作方案恢复必要意图；不要求用户先补齐。原稿/-r2版本按用户选择和实际交接确认，不凭文件名自行认定最新有效。
  - 粗剪草稿：可选CapCut工程或其他可访问原片；同名/同时长只作候选，须实际核对对应关系。默认仍可仅从粗剪mp4精剪，不因缺工程停工。
- **交付**（写到 `自媒体 2/精剪成片/`）：
  - 默认只导出一个 MP4。有配乐时输出 `<Name>_精剪_BGM.mp4`；只用原声时输出 `<Name>_精剪_原声.mp4`。仅在用户明确要两版时为 `mix` 传 `include_no_bgm=True`，另出无配乐版。自定义分集脚本也按此规则，质检只检查所选版本。
  - 成片末尾带 2 秒品牌片尾
  - `<Name>_剪辑说明.md`
  - CapCut 草稿**默认不做、不装**（用户 2026-10-31 定：草稿里的字幕和成片样式对不上，不需要）；只在用户明确要草稿时做第 5 步
- **过程文件**：放在那一期的 `过程稿/精剪/`，包括`接收与差异.md`、`episode.py`、`体检/`、`timeline.json`、质检报告、`capcut/`。接收记录使用[模板](templates/intake-record.md)，由助手定位实际变化，用户无需逐条填写。
- **运行环境**：使用工作台的 Python。离线依赖与媒体工具随包，见[迁移与运行](PORTABLE.md)。

## 步骤
设 `P=python3`，`T=<本目录>/finecut`，`E=<那一期>/过程稿/精剪`。
0. **接收**：读取制作交接和用户最新修订，核对实际粗剪及声音材料；在接收记录中把关键内容、必留画面/表演映射到实际粗剪时间。允许外部重排/替换，不自动恢复原稿。新粗剪或同名文件变更后重做受影响的定位、EDL及声音事件，不能只换文件或刷新指纹。
   分段粗剪先拼：`$P $T/assemble.py <段落目录> $E/rough_<名字>.mp4 [--files …]`，下面的“粗剪”都指这条拼接稿，段落版本与指纹在 `$E/segments.json`。
1. **体检**：`$P $T/analyze.py <粗剪.mp4> $E/体检`。
   - 默认仅列名称/时长近似的草稿候选，不自动用草稿边界；`--draft`也仅指定候选。实际核对对应关系后，才加`--draft-verified --draft-verification-note "实际核对依据"`使用主轨边界；无需用户逐次批准，助手核对不足则继续按视频检测。
   - 体检登记实际粗剪指纹；渲染和质检核对已有版本，变更须重核时间定位。缺体检或源指纹时先完成体检。
   - 读`体检报告.md`，逐张看`shots_*.jpg`并实际观看必要范围，结合制作意图、用户修订与当前故事判断问题；缩略图/词表不能代替表演和因果检查。
   - 疑似爆音和疑似重复/拖沓只是候选，要自己看图、看波形判断。
2. **节拍**：`$P $T/beats.py <BGM> $E/bgm_beats.json`。
3. **写 `$E/episode.py`**：参考最近一期的结构，按本次素材重新写EDL和声音事件，不复制旧源路径或时间（参考包内 [example_episode.py](templates/example_episode.py)）。
   - 剪辑表用当前实际粗剪时间写，每行注明内容；设计时间只作线索，用户必留内容落实到EDL和成片复核位置；删掉的段落注释写明原因，不删除用户要求保留的表演。
   - 写配乐编排 `music_plan`、修音 `AUDIO_FIXES`、事件 `EVENTS`。
   - 事件是质检唯一的客观对齐依据：撞击、音乐切断、音乐重进都要写进去。
   - **品牌片尾每期都加**（2 秒，用户 2026-10-28 要求；16:9 长片自动换成同商品的 10 秒 YouTube 结束画面 `PuggyRoom_EndScreen16x9_<商品>.mp4`，和竖版片尾设计不同：两个视频位 + 订阅圈留给 YouTube Studio 的结束画面元素，剪辑说明里提醒发布时在 Studio 把元素放到这三处）：`mux` 和 `save_timeline` 默认就会接上，商品位按 ISO 周在 tote/mug/tee 之间轮换，不用另外写参数。只有用户明确说某期不要时才传 `outro=None`（两处都要传）；指定商品用 `outro=outro_clip("mug")`（两处都要传）。按含片尾的最终成片验收，达到 60 秒即可。交接中的规划区间仅供参考。片尾素材由 `品牌片尾/make_sting.py` 生成。
   - 然后运行 `$P $E/episode.py`。
4. **质检**：`$P $T/qa.py $E`。
   - 读 `质检报告.md`，看 `qa_cuts.jpg` 和 `qa_timeline.png`。
   - 偏差大时先怀疑自己的预期时间写错了、或者测量有误，再怀疑成片。
5. **剪映草稿（仅用户明确要求时）**：`$P $T/capcut_export.py build $E "<草稿名>"`，自检必须通过。
   - 安装前让用户先在 CapCut 里 Cmd+Q 退出，再运行 `install`。
   - 不覆盖同名草稿，安装会备份 `root_meta_info.json`。
6. **写剪辑说明**，包含：
   - 交付文件和响度（注明正片时长、加片尾后的总时长，以及用的是哪个商品版片尾）
   - 体检发现的问题及处理方式
   - 节奏与配乐
   - 剪辑表
   - 用户必留内容的实际保留位置、外部调整的承接、删掉的部分及仍缺素材
   - 已测量和没验证的项（我没法试听，要请用户重点听哪几处）
   - BGM 授权未知的提醒

## 剪辑原则（用户反馈过的）
- 含片尾的成片至少 60 秒。猫不说话。CCTV 叠字（REC/CAM）只能加在监控视角的镜头上。
- **字幕**（用户 2026-10-28 定）：用户这一期没要求字幕就**不加**，不要主动提议。要求了就**只用品牌动效字幕** `brand_captions.burn_brand_captions`。品牌动效字幕的规格：
  - 字体字号：Bricolage ExtraBold，128px
  - 文案：首字母大写、句末带句号，旁白口吻，只补画面读不出的因果
  - 配色：奶油字、墨色描边、硬投影；`*关键词*` 压在黄色胶囊上
  - 动效：逐词回弹弹出；落空用 shake，反转或收尾用 slam
  - 位置：放在画面中下，逐条避开猫脸和关键动作
  - 出图：渲染前先出样帧检查
  - 剪辑说明：注明 CapCut 草稿只带静态样式，没有动效和胶囊
- **节奏要紧**：删真正重复和无变化的等待；完整奇观、动作中的表情、因果与回收按实际观看价值保留，尤其不能让默认狠剪、去重或卡拍覆盖用户必留要求。
- **配乐**：在笑点那一帧让 BGM 当场断掉，留冷场；下一场在小节头重进，用原曲结尾段收住全片。BGM 压低约 7dB，画内声出现时让开（1018 那期用户试听认可）。
- **爆音**：粗剪里孤立、削波的“啪”这类声音，压低约 8dB，不要删（1018 那期用户认可）。
- 实际内容与原稿不同先判断来源：用户已明确调整的直接承接；未说明的普通变化结合实际效果处理，不自动判错。影响核心因果或必留意图且无法判断时只澄清该处，其余继续。生成问题能剪辑修复则说明处理，不能修复的列为实际限制。

## 已知限制
- 默认渲染和草稿从实际粗剪mp4取素材；原片是否可访问以当前环境核查为准。用户已提供可读原片时可在授权内使用，但不暗示当前单粗剪渲染器自动支持多源EDL。粗剪已混BGM且无独立原声时，不能把再导出误称真正无BGM版。
- CapCut 草稿里没有：BGM 自动让开、淡入淡出、响度标准化。剪辑说明里要写明这一点。
